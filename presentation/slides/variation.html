Part 1 · the same question, five answers

Ask one model the same question five times

Order 1042 has an accepted payment. The email with the game key is in the send queue. “What is the status of order 1042?” Five new chats give five answers.

Chat 1

The order has been paid.

FAIL: not a status value

Chat 2

Status: PROCESSING

FAIL: not a permitted value

Chat 3

Awaiting fulfilment. The key email is queued.

FAIL: not a status value

Chat 4

Payment accepted, delivery pending.

FAIL: not a status value

Chat 5

PAID

PASS: code can use it

Each answer is defensible. A model gives a probability, not a lookup. All five are likely continuations of the same prompt.

Only one is usable. A system cannot act on an answer if it cannot predict the shape of the answer.

An agent does this in each turn. Which tool, which argument, when to stop: each decision is a point where the result can change.

GE 01 · five example answers. Use the instrument in the course to get your own.

Do the experiment live if you can. The five answers on the slide are examples, not a recording. The point is not that the model is bad; each of the five is reasonable. The point is that code downstream can use only one of them, and you cannot know in advance which chat gives it. Part 4 comes back to this: the correct status is PAID.
