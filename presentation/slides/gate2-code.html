def gate_2(call, result, facts) -> Result:
    for rule in RULES:
        if not rule.holds(facts, result):
            return Reject("GATE 2", rule.id, rule.text)
    return Accept(result)

# the check and the commit are one transaction, or they are nothing
with db.transaction() as tx:
    facts   = tx.facts_for(call.order_id)
    verdict = gate_2(call, result, facts)
    if verdict.rejected:
        tx.rollback()
        return back_to_model(verdict.text)  # nothing was lost
    tx.apply(result)

A cardinality rule in the ontology should also be a constraint in the database. Then the rule survives a bug in your gate.

The pure-agent rule pays for itself here: because the agent changed nothing during the loop, a rejection costs one rollback and a retry. Say the last part plainly — every cardinality rule gets a unique constraint. The gate is the fast, explainable check; the constraint is the one that holds when the gate has a bug.
