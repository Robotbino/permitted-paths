Part 4 · control 3

Two gates around every tool call

while the task is not complete:
    proposal = the model suggests a tool call
    # GATE 1: is the shape of the call correct?
    result = the tool makes a result, with no change to data
    # GATE 2: does the result obey the ontology?
    record the change, or send the cause back to the model

Gate 1 — input, before the tool operates

The shape of the call: types, ranges, necessary fields. It reads only the call.

Gate 2 — output, after the tool operates

The sense of the result: cardinality, roles, agreement with the state of the world. It reads the call, the result, the ontology and the current facts.

The rule — a pure agent

The agent calculates and gives a result. It does not change the world during the loop.

The third row is the important one. If the agent changes no data during the loop, you can reject a result and lose nothing. Do the Gate 2 check and the commit in one transaction, and add a unique constraint in the database for each cardinality rule.
