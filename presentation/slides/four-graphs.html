Part 3 · which graph do you mean?

Four things carry the name “graph”

TypeQuestionNodes areLife
Execution graphWhat comes next?Units of workThe design is permanent. Each run is one pass.
Knowledge graphWhat is in the domain?Entities — a customer, a fileContinues across runs
Context graphWhat occurred in this run?Steps, tool calls, records usedPermanent. Each run adds a trace.
Procedural graphWhich paths are permitted?Steps of a procedurePermanent. Many runs use it again.

The execution graph and the procedural graph are about control. The knowledge graph and the context graph are about data.

A procedural graph is data that a harness loads. An execution graph is code that the runtime enforces.

Two causes of confusion: GraphRAG is about data, not control. And a context graph is a graph of traces — it is not the context window of a model.

GE 03 · the course puts one loan decision under all four lenses

Most disagreements about “graphs for agents” are two people meaning different rows of this table. Fix the vocabulary here and the rest of the conversation gets easier. The cycle: the run obeys a procedure, reads facts from the knowledge graph, writes its steps to the context graph, and good runs become a better procedure.
