How one run makes the next run better

The intelligence plane is a loop. Each run goes around it one time.

1 · Ontology

Types, values and rules. Each rule has an id.

2 · Gate

Each result of the run gets a check against the rules.

3 · Trace

One row for each step: the node, the rule id, PASS or FAIL.

4 · Query

Which rule gives FAIL most? Which fact was absent?

5 · correct the rule, or add the fact that was absent

The amber arrow is the important one. If the trace does not go back into the ontology, the system makes the same error in the next run.

The rule id carries the lesson. A trace with no rule id is a log. You can read it, but you cannot count it. The next slide gives the row and the query.

PART 5

Walk the loop once with the refund example: rule LV-1 is in the ontology; gate 2 checks a refund against it; the trace row records GATE 2, LV-1, FAIL; a weekly query shows that LV-1 fails more than any other rule; you learn that the model was never told that an order was already refunded, so you add that fact to what the plan step retrieves. The next run needs one attempt, not two.
