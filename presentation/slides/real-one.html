Part 7 · a small real one

One developer, Markdown files, a legacy application

A legacy enterprise web application with a workflow engine, many pages and many business rules, where the documents and the code do not always agree. The solution was one note for each claim, with a type, a confidence value and a source.

Without the structureWith the structure
The agent searches the code for a ruleThe agent starts at the rule note and follows a link to the code
The agent writes a claim with no evidence as a factEach claim has a confidence value and a source
You cannot see a conflict between the document and the codeThe conflict is a status value and an open question
The agent session loses its knowledge at the endThe closeout step writes the knowledge to the graph
“Is it complete?” is an opinionA check gives PASS or FAIL

The agent does not make a claim with no evidence. It reads the confidence and the status. A conflict is an explicit node, and you can see it.

GE 07

No graph database, no platform, no budget. Five to eight note types with a short prefix each, in a folder. The last row is the one that changes meetings: “is it complete” stops being a matter of opinion.
