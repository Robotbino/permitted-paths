The sequence in which to make it

Each step is useful alone, and each step makes the next step easier. Do not start with the graph.

WhenWhat you makeHow you know that it operates
Hour 1Find one rule in one prompt. Make it an enumeration and a validator.Measure the variation before and after, with the procedure of part 1.
Day 1Gate 1 on each tool: a schema for each call, no extra fields.Calls with an incorrect shape do not get to your tools.
Week 1Make the agent pure. Add Gate 2 and the database constraints.A rejected result causes a rollback and no other change.
Week 2Write the trace: one row for each step, with the rule id and PASS or FAIL.A query answers “which rule gives FAIL most?”
Week 3Now the execution graph: move the sequence into NODES and EDGES.The edge functions have tests that use no model.
Month 2Use the trace: correct the rules that give FAIL most, add the absent facts.The same task needs a smaller number of attempts.

If you do only hour 1, you moved one decision from the model to the system. That is the course.

Controls 2 and 3 first. Control 1 last.

PART 8

Say the ordering out loud, because it is the opposite of what people expect. Gates and ontologies are cheap, local and useful on day one. The graph is the biggest change and the one most likely to be rebuilt, so it comes after you have traces that show where the run actually goes.
