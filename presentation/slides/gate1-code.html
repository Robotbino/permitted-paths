Gate 1: is the shape of the call correct?

class RefundCall(BaseModel):
    model_config = ConfigDict(extra="forbid")
    order_id:     int
    amount_cents: PositiveInt
    reason:       Literal["duplicate", "faulty", "goodwill"]
    currency:     Literal["EUR", "GBP", "USD"] = "EUR"

TOOL_SCHEMAS = {"refund": RefundCall, "search_notes": SearchCall}

def gate_1(name: str, args: dict) -> Result:
    schema = TOOL_SCHEMAS.get(name)
    if schema is None:
        return Reject("GATE 1", f"no tool named {name!r}")
    try:
        return Accept(schema.model_validate(args))
    except ValidationError as e:
        return Reject("GATE 1", readable(e))  # goes back to the model

Before the tool operates

Gate 1 reads only the call. It is cheap, it needs no database, and it catches the largest group of failures: a well-written call to a tool that does not exist, or with an argument that was invented.

Forbid extra fields

One line. Without it, a model that adds force=true gets silently ignored today and silently honoured after someone adds that parameter next year.

Write the rejection for a reader

The text goes back into the model's context. “amount_cents must be greater than 0” repairs the next attempt; a stack trace does not.

Control 3, first half · the same schema generates the tool definition the model sees

Two practical notes. One: generate the tool definition the model is given from this same class, so the schema and the documentation can never drift apart. Two: a Gate 1 rejection is not an error to log and forget — it is a message to the model, so spend a minute on its wording.
